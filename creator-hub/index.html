The shared engineering DNA

One creator. Different products. The same standard of reasoning.

The common thread is not color, logos or a shared runtime. It is how difficult software behavior is made explicit.

01

Typed over stringly

Prefer CLR types, explicit result models and compile-time discoverability over generic extension bags and magic strings.

02

Evidence before claims

Runnable examples, tests, benchmarks and explicit contracts are more useful than vague trust badges or marketing adjectives.

03

Boundaries are features

A trustworthy tool explains where it stops: Forge does not execute; Causalia does not replace real-provider verification.

04

Deterministic explanations

If a library plans, parses, simulates or maps something, users should be able to inspect why that result exists.

DELIBERATE NON-GOAL

This is not a platform.

Causalia, Forge and GORM should remain independently useful. The creator identity connects them for discovery; it does not create a PjotrCasteel.Core dependency, shared runtime, or umbrella framework.

Open Source Design DNA

Share principles.
Do not share personality.

The creator-level design constitution defines README structure, website quality, writing voice, accessibility, trust signals and authorship—while explicitly forbidding a universal theme or component library.
