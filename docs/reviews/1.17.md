# Forge 1.17 review — typed derived facts

## Capability

Forge can derive strongly typed facts from context and other facts until a stable monotonic snapshot is reached.

## Type and security properties

- Public lookup uses `FactKey<T>`; no string key registry exists.
- Consumers normally extend `FactRule<TContext, TFact>` and only read/write typed values.
- Derivation is monotonic: an existing key cannot silently change value. Conflicts fail explicitly.
- `maxPasses` bounds custom-rule behavior so a broken extension cannot loop indefinitely inside Forge.
- No reflection, dynamic compilation, assembly scanning, or deserialization is used.

## Performance

Rules run in deterministic list order. The common cost is O(passes × rules), with propagation ending immediately when a pass adds no facts.
