# 1.0 alignment review

## Product identity

Forge 1.0 stabilizes two production primitives:

- `Forge.Delta`: semantic state differences and conflict/reversal primitives;
- `Forge.Sync`: desired-state reconciliation and planning primitives.

The release is intentionally broader than the original prototype. It now covers the lifecycle from state comparison through typed planning and portable approval boundaries without crossing into execution.

## Capability checklist

### Delta

- generated semantic equality;
- typed and flattened nested changes;
- custom equality and ignored state;
- external type profiles;
- explicit collection equality semantics;
- three-way semantic conflict analysis;
- exact Delta inversion;
- equality-consistent in-process semantic hash;
- portable Delta manifests.

### Sync

- generated same-type keyed reconciliation;
- Replace and partial-Upsert semantics;
- composite/custom logical keys;
- explicit nested Sync;
- cross-type reconciliation;
- ordered fallback identities for systems with instance and business keys;
- typed operation classification;
- dependency execution/delete waves and cycle detection;
- ordered async streaming reconciliation;
- validated node/edge topology reconciliation;
- compensation inversion for complete plans;
- portable manifests;
- stale-plan preconditions;
- canonical SHA-256 plan identity;
- heterogeneous batch composition and batch-wide validation.

## Boundary review

Runtime source contains no Fulfilment, TMF, SPIS, GORM, Dapr or KPN concepts. Dogfood uses those domains only as pressure tests.

Forge still does not:

- persist state;
- execute operations;
- publish messages;
- call external systems;
- decide cancellation/PONR/business policy;
- provide distributed locking or transactions;
- mutate domain objects automatically.

That boundary is considered part of the 1.0 product contract.

## Release-gate status in artifact environment

Static repository validation passed. The artifact environment does not provide a .NET SDK, so build/test/pack/AOT/package-consumer gates are defined in CI but cannot truthfully be reported as executed here. Public NuGet publication should require a green CI run.

The NuGet hardening pass also requires package-specific READMEs, XML documentation, `.snupkg` validation, isolated packed-package consumers, SDK package validation and retained CI package artifacts. See `docs/NUGET.md`.
