# 0.28 review — stale-plan preconditions

## Capability

Portable Sync manifests can be checked against a fresh portable current-state snapshot before execution. Add operations require absence; update/remove operations require the item to still exist with the exact captured portable current state.

## Production value

Approval, outbox and deferred execution create a time gap between planning and acting. Without preconditions, an otherwise valid plan can silently overwrite state that changed after it was calculated.

## Boundary

Forge detects staleness but does not retry, merge or execute. The application chooses whether to reject, re-plan or run three-way conflict analysis.
