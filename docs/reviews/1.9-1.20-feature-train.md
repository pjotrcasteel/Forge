# Forge 1.9-1.20 feature train review

The 1.9-1.20 train deliberately stays inside Forge 1.x: it adds compatible typed planning capabilities rather than using a major version as a feature counter.

| Version | Capability | Production boundary |
| --- | --- | --- |
| 1.9 | Typed conditional dependencies | State semantics supplied by `IStateCondition<TState>` |
| 1.10 | Typed readiness | Application supplies requirements and reason type |
| 1.11 | Plan slicing | Forge adds transitive predecessor closure |
| 1.12 | Typed provenance | Application owns cause-node types |
| 1.13 | Plan-to-plan Delta | Separate typed operation/dependency reconciliation |
| 1.14 | Execution-aware replanning | Running/completed work cannot be silently replaced |
| 1.15 | Approval scopes | Structural scopes only; no auth/user model |
| 1.16 | Alternative plans | Application metrics and preference policy |
| 1.17 | Typed facts | `FactKey<T>`, monotonic bounded propagation |
| 1.18 | Scenario matrices | Lazy combinations, explicit cancellation |
| 1.19 | Plan templates | Generated typed instantiation; app-owned build logic |
| 1.20 | Composite topology | Typed cross-topology invariants and ordering |

## Cross-cutting review

### Strong typing

The new normal-path APIs contain no string state names, operation registries or `Dictionary<string, object>` policy bags. The consumer may choose `string` as its own domain key, but Forge does not force that representation.

### SOLID

Policy-facing abstractions are narrow. New consumer behavior is added through interfaces/base rules rather than switches in Forge. Orchestration/execution remains outside the library.

### Security

No feature adds reflection discovery, arbitrary type activation, dynamic compilation, hidden I/O or executable deserialization. Fact propagation is bounded and async scenario evaluation is cancellation-aware.

### Performance

Reconciliation uses hash indexes. Graph operations use iterative O(V + E) traversal. Provenance shortest-path links are cached during BFS. Readiness avoids allocating a reason list for runnable items. Scenario combinations are lazy.

### Final-review defect found

The initial 1.17 implementation used a generic-static counter inside `FactKey<T>`, which could assign the same internal ID to facts of different value types. Final review replaced it with one process-wide non-generic identity source and added a cross-type regression test. This fix is included in the final 1.20 source.

## Remaining external gate

This environment does not provide a .NET SDK, so no claim is made that `dotnet build`, `dotnet test`, `dotnet pack`, Native AOT or package validation executed here. Those existing CI gates remain mandatory before NuGet publication.
