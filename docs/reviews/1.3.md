# Forge 1.3 review — Operation rules

## Capability

Structural changes can now be classified through ordered, deterministic application rules instead of one hand-written selector switch.

The first matching update rule wins. Add/remove/fallback-update operations remain explicit required configuration. The selected rule is attached to the 1.1 explanation model.

## Example

```csharp
var rules = new SyncOperationRules<Item, ItemSync.Key, ItemDelta, Operation>(
        Operation.Add,
        Operation.Delete,
        Operation.Modify)
    .WhenUpdated(
        "replace.product",
        "Changing product requires replacement.",
        update => update.Delta.ProductChange.HasChanged,
        Operation.Replace);

var result = rules.Plan(plan);
```

## Boundary

Forge evaluates rules supplied by the application. It does not define what Add, Modify, Replace or Delete mean and performs no execution.
