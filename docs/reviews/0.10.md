# Milestone 0.10 review — real dogfood baseline

## Goal

Validate Forge against code that exists in the current Fulfilment service rather than only synthetic samples.

## What changed

- Fixed a release-blocking Sync generator bug that emitted the desired-item loop twice.
- Added dogfood coverage modeled directly on `CharacteristicUpsertPlanner` from the current Fulfilment service.
- Demonstrated replacing the planner's hand-written five-property `HasChanges` comparison with a generated Delta state model.
- Kept partial-update semantics out of Sync for now: the current characteristic payload is an upsert subset, not a complete desired-state collection.

## Alignment review

Forge remains generic. No Fulfilment, TMF, SPIS, graph persistence or event concepts were added to runtime packages or generators. The service-shaped code lives only in dogfood tests/documentation.

The dogfood exercise reinforced the product boundary:

- Delta is already directly useful in current production-style code.
- Sync needs an explicit partial/upsert policy before it should be used for partial characteristic payloads.

## Decision

Proceed. External-type configuration is the next maturity gap because production consumers should not need to own or annotate every compared model.
