# Milestone 0.17 review — performance and release-quality measurement

## Goal

Improve obvious hot paths without changing Delta/Sync semantics for benchmark convenience, and make future performance claims reproducible rather than anecdotal.

## What changed

- Generated Sync now exposes allocation-light `AreEquivalent` overloads for Replace and Upsert semantics.
- Nested Sync classification recursively calls child `AreEquivalent` instead of constructing a child `SyncPlan` just to test `HasChanges`.
- Unordered-list comparison uses frequency counting rather than repeated searches.
- Keyed-list and dictionary comparison use indexes rather than nested scans.
- Benchmarks now cover top-level Sync equivalence, nested Sync equivalence, detailed plans and collection comparers.
- A manually triggered GitHub workflow runs BenchmarkDotNet on .NET 10 and uploads machine-readable and Markdown results.
- `docs/PERFORMANCE.md` defines the benchmark/claim policy.

## Correctness review

The generated Sync equivalence path preserves the same logical-key rules as `Plan`:

- duplicate current keys are rejected by the shared current index;
- duplicate desired keys are rejected explicitly;
- Replace considers current-only items a difference;
- Upsert intentionally permits current-only items because they would be `Preserved`;
- additions and mutable/nested updates are differences in both modes.

The detailed `Plan` path remains authoritative when the application needs operation records or nested child plans.

## Alignment review

No persistence, transport, workflow, Fulfilment or other application-specific behavior entered the runtime packages. Performance work remains behind the same public semantics. `AreEquivalent` is a general state question rather than a workflow shortcut.

The collection optimizations retain explicit comparer semantics; Forge still does not guess whether a collection is a sequence, set, dictionary-like structure or reconciliation boundary.

## Validation limitation

This workspace still has no .NET SDK and outbound SDK download is unavailable. The milestone can therefore be structurally validated here, but the checked-in test, benchmark, package-consumer and Native AOT gates must run on a real .NET 10 runner before publication. No benchmark numbers are inferred or invented.

## Decision

Milestone 0.17 is the requested stop point. Do not start another feature milestone from this release train. The product is materially more mature than the earlier prototype, but additional pre-1.0 work can be planned separately after reviewing real usage and measured benchmark output.
