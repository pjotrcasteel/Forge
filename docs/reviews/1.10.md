# Forge 1.10 review — typed readiness evaluation

## Capability

Forge can now evaluate whether plan items are runnable from a consumer-defined set of strongly typed requirements. Conditional state dependencies compose through the same model.

## SOLID boundary

- `IReadinessRequirement<TContext, TReason>` has one responsibility.
- `IReadinessRequirementProvider<TItem, TContext, TReason>` lets applications add requirements without changing Forge.
- Blocking reasons are application types, not Forge strings or dictionaries.
- Forge evaluates readiness only; dispatch remains application-owned.

## Performance and safety

Evaluation is O(items + requirements), preserves input order, has no reflection or hidden I/O, and snapshots result collections.
