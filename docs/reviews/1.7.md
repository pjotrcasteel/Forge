# Forge 1.7 review — Conflict resolution

## Capability

Three-way merge is no longer diagnostic-only. Generated `AnalyzeMerge` output can be converted into a semantic merge patch.

Non-conflicting current/desired changes are combined automatically. Conflicts can be resolved per path or through a default policy using current, desired, baseline or custom application logic. Missing policies remain explicit unresolved conflicts.

## Boundary

Forge does not construct or mutate arbitrary domain objects because generated Delta supports immutable/read-only types for which safe reconstruction is not universally possible. 1.7 returns the resolved semantic patch; the consumer decides how that patch is materialized.

## Why this is a feature

Applications can now build optimistic-concurrency/configuration merge flows on top of the same Delta semantics rather than merely displaying conflicts.
