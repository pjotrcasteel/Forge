# 0.18 review — cross-type reconciliation

## Capability

Forge.Sync can now reconcile a current collection and a desired collection with different CLR item types while retaining logical-key, Replace/Upsert, duplicate-key and typed-delta semantics.

## Why this is not cosmetic

Layered applications routinely compare persistence models, domain models, API contracts and provider responses. Requiring both sides to be the same CLR type forced projection boilerplate outside Forge.

## Alignment

- no reflection;
- no persistence or transport knowledge;
- application supplies mapping/equivalence semantics explicitly;
- Forge owns deterministic keyed reconciliation.

## Follow-up pressure

Cross-type Sync makes conflict analysis and operation planning more valuable because current and desired state can now originate from different architectural layers.
