# Forge 1.8 review — Plan simulation

## Capability

Portable Sync manifests can now be simulated against a current-state snapshot without executing infrastructure code or mutating domain objects.

Simulation first runs the existing stale-plan preconditions. If the plan is stale, it is not applied and the original snapshot is returned. If valid, Add/Update/Remove operations are projected into a new immutable portable state snapshot.

`ManifestSimulationResult.Matches(...)` lets tests, preview screens and planners prove that the projected state equals an expected target under Forge's portable JSON semantics.

## Why the manifest boundary

The same simulator now works for:

- generated same-type Sync;
- cross-type Sync;
- persisted/outbox plans;
- approval previews;
- replay/audit tooling.

It also naturally preserves untouched state for Upsert manifests because only actual operations are applied.

## Boundary

Simulation is state projection only. It does not claim external side effects succeeded and never replaces execution or SPIS/Inventory integration tests.
