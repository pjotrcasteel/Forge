# Forge 1.4 review — Incremental replanning

## Capability

Portable structural plans can now be replanned while preserving application-owned operation identities only when the operation is semantically unchanged.

Forge compares canonical one-operation manifest digests. The result separates:

- retained operations;
- newly required operations;
- operations no longer required;
- operations replaced because their semantic payload changed.

## Why manifest semantics

Matching only on `key + Update` would incorrectly retain an operation when its desired state changed. Reusing the canonical manifest digest means identity retention follows the same portable semantics used for plan approval and audit.

## Boundary

Forge does not create operation IDs. The application supplies an ID factory, so there is no hidden randomness or persistence assumption.
