# Milestone 0.15 review — rich configuration

## Goal

Make external-type profiles genuinely usable instead of merely generating a Delta over every public property.

## What changed

External profiles can now exclude technical state and configure domain equality without changing the target type:

```csharp
[GenerateDeltaProfile(typeof(ExternalCustomer))]
[DeltaProfileIgnore(nameof(ExternalCustomer.Id))]
[DeltaProfileComparer(nameof(ExternalCustomer.Name), typeof(IgnoreCaseComparer))]
public sealed class ExternalCustomerProfile
{
}
```

The generator validates property names, comparer types, comparer constructibility and conflicting configuration at compile time.

## Alignment review

Configuration is still compile-time and reflection-free at runtime. The profile API covers the most important external-model concerns—participating state and equality—without introducing a service locator, runtime registry or expression compilation.

Normalization is intentionally represented through equality comparers for now. Computed/projected members remain out of scope until a real use case proves that they belong in Delta rather than in an application-owned comparison state model.

## Decision

Proceed. The next maturity step is diagnostics/tooling: configuration mistakes and generated API behavior should be easy to understand from the compiler and IntelliSense.
