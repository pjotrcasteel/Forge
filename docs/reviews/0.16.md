# Milestone 0.16 review — diagnostics and tooling

## Goal

Move configuration mistakes from surprising runtime behavior into clear compile-time feedback and improve the debugging experience of generated state.

## What changed

- Empty generated Deltas now produce a warning.
- `DeltaComparer` combined with `DeltaIgnore` produces an ineffective-configuration warning.
- A `SyncNested` property cannot also be a logical Sync key.
- The diagnostics catalog now documents every current generator diagnostic.
- Generated Delta types and Sync keys have debugger displays.
- Runtime `ValueChange<T>`, `PropertyChange` and `SyncPlan` have concise debugger displays.

## Alignment review

No runtime behavior is hidden behind tooling. Diagnostics only reject ambiguous/unsafe configuration or warn about configuration that has no effect. Debugger metadata changes observability, not semantics.

A full IDE code-fix package is deliberately deferred. It would add another distributable/analyzer surface before the core API has had enough production usage to know which fixes are genuinely valuable.

## Decision

Proceed to 0.17. The final requested milestone should measure and improve hot paths—especially nested Sync classification and collection comparers—without changing semantics merely to win benchmarks.
