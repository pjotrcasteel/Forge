# Forge 1.2 review — Generated cross-type profiles

## Capability

Consumers can declare a source-generated profile over two different CLR types and get a reflection-free `Plan`, `AreEquivalent` and `Between` implementation.

Identity routes are explicit and ordered. State mappings are explicit. Generated code calls `CrossSync` directly and emits a portable `CrossTypeDelta` for mapped differences.

## Example

```csharp
[GenerateCrossSyncProfile(typeof(StoredLine), typeof(RequestedLine))]
[CrossSyncIdentity(nameof(StoredLine.Id), nameof(RequestedLine.Id))]
[CrossSyncMap(nameof(StoredLine.Name), nameof(RequestedLine.Name))]
[CrossSyncMap(nameof(StoredLine.Quantity), nameof(RequestedLine.Quantity))]
public partial class StoredLineProfile;

var plan = StoredLineProfile.Plan(current, desired);
```

## Deliberate boundary

All identity routes in one generated profile must use the same key type. More complex heterogeneous fallback identities remain supported through the lower-level `CrossSyncMatchDefinition`, which is safer than silently stringifying unrelated identity types.

## Why this is a feature

Before 1.2 every cross-type reconciliation required hand-written selectors, equivalence and Delta delegates. The generated profile makes the common layered-model case first-class while preserving the manual escape hatch for advanced matching.
