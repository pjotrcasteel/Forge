# Forge 1.9 review — typed conditional dependencies

## Capability

Forge can now represent and evaluate dependencies whose prerequisite is a strongly typed predecessor state rather than an untyped label.

## Production properties

- Keys and states remain generic application types.
- Missing predecessor state is distinct from an observed state that fails the condition.
- Consumers extend state semantics through the single-method `IStateCondition<TState>` interface.
- Evaluation is deterministic, side-effect free, and O(E) in the number of conditional dependencies.
- No reflection, dynamic activation, string lookup, hidden I/O, or application workflow execution was introduced.

## Boundary

Forge evaluates dependency satisfaction. The application still owns state transitions and dispatch.
