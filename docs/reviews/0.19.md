# 0.19 review — three-way semantic conflict analysis

## Capability

Every generated Delta now exposes `AnalyzeMerge(baseline, current, desired)`. It produces both branch deltas and strongly explained conflicts when the same semantic property changed differently on both branches.

## Why this is not cosmetic

Long-running workflows, optimistic concurrency and desired-state reconciliation need to distinguish independent changes from conflicting changes. Two-way diff cannot answer that question.

## Semantics

Conflict checks reuse generated Delta equality semantics, including configured comparers and nested generated values. The analysis intentionally does not construct or persist a merged domain object; application policy remains responsible for choosing and applying a resolution.

## Alignment

No workflow, persistence or transport assumptions were introduced.
