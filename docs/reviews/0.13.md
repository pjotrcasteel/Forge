# Milestone 0.13 review — Sync policies

## Goal

Prevent a partial update payload from being mistaken for a complete desired-state snapshot.

## What changed

Generated synchronizers now expose:

```csharp
ItemSync.Plan(current, desired); // Replace semantics
ItemSync.Plan(current, incoming, SyncMode.Upsert);
```

`Replace` means current-only items are `Removed`.

`Upsert` means current-only items are `Preserved`; incoming items are still added or updated normally.

`SyncPlan` now has a first-class `Preserved` bucket so no items disappear from the plan merely because policy suppressed removal.

## Real-service validation

This directly models the current Fulfilment characteristic update behavior: a SPIS payload containing only `ipSubnet` must not imply removal of `materiaaltype` or `bandbreedte`.

## Alignment review

Policy remains structural rather than domain-specific. Forge knows only whether the supplied collection is complete replacement state or a partial upsert. It still does not know about SPIS, PATCH, messages or persistence.

An `AddOnly` mode was deliberately not added. Its treatment of existing-but-different items is ambiguous enough that it should be driven by real usage instead of guessed now.

## Decision

Proceed. Nested reconciliation is now the next major capability: parent updates should be able to expose meaningful child add/update/remove plans rather than only a collection-level changed flag.
