# Milestone 0.12 review — collection semantics

## Goal

Make collection comparison explicit enough for rematerialized domain state without turning Delta into an implicit reconciliation engine.

## What changed

Forge.Delta now provides reusable comparers for:

- ordered `IReadOnlyList<T>` sequence equality;
- unordered list equality that preserves duplicate multiplicity;
- set-style list equality that ignores order and duplicates;
- order-independent `IReadOnlyDictionary<TKey, TValue>` equality;
- order-independent keyed-list equality through a compile-time `IKeySelector<T, TKey>`.

## Alignment review

The package still does not guess whether a collection is a sequence, set or keyed aggregate. The consumer opts into the intended semantics with `DeltaComparer`, keeping domain meaning explicit.

The keyed comparer compares both logical identity and item value. It is deliberately not a replacement for Forge.Sync: it only answers equality and does not create add/update/remove plans.

## Decision

Proceed. The next milestone should add explicit reconciliation modes so complete desired state and partial upsert payloads cannot be confused.
