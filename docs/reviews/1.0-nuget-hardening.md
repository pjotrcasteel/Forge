# 1.0 NuGet hardening review

## Goal

The product has been dogfooded in Fulfilment and Inventory. This pass deliberately adds no reconciliation capability. Its purpose is to make the public package boundary as trustworthy as the source/project-reference boundary already proved to be.

## Improvements made

### Package-specific onboarding

`Forge.Delta` and `Forge.Sync` now ship different NuGet READMEs.

A user installing Delta sees Delta first. A user installing Sync immediately sees Replace/Upsert reconciliation and learns that Delta is included transitively. The full repository README remains the product-family document.

### SDK package validation

Both public package projects enable `EnablePackageValidation` during pack.

There is no baseline package for the initial 1.0 release. After 1.0.0 is public, future stable releases should validate against the latest previous stable version through `PackageValidationBaselineVersion`.

### Debugging contract

Both packages keep `.snupkg` generation and now opt into repository metadata through `PublishRepositoryUrl`. `EmbedUntrackedSources` keeps non-linked build inputs available to portable PDBs where applicable.

The .NET 10 SDK provides Source Link support for the common git providers, so no explicit Source Link package dependency is added.

### Strong package inspection

`eng/verify_packages.py` now verifies more than the presence of two DLLs.

It checks:

- package ID and version;
- MIT license expression;
- focused README;
- changelog and license payload;
- runtime DLL + XML docs;
- generator placement;
- no Roslyn DLL leakage;
- no C# source leakage;
- Delta has zero NuGet dependencies;
- Sync depends only on the matching Delta version;
- `.snupkg` exists and contains the runtime PDB.

A synthetic package smoke test was used in the artifact environment and caught a false-positive bug in the first version of the verifier. The verifier was corrected and the synthetic valid package set now passes.

### Isolated packed-package consumers

There are now two package-consumer boundaries:

```text
Forge.Delta.PackageConsumer
    -> Forge.Delta only

Forge.PackageConsumer
    -> Forge.Sync only
    -> proves Delta runtime + generator arrive transitively
```

The Sync consumer also exercises ordered fallback identity, which was introduced by Inventory dogfooding.

Each consumer receives a fresh `NUGET_PACKAGES` directory in CI. A developer machine or runner cache therefore cannot hide a missing dependency or incorrectly packed generator.

### Downloadable CI candidates

CI computes SHA-256 checksums and uploads `.nupkg`, `.snupkg` and `SHA256SUMS.txt` as an artifact. A package can therefore be downloaded and used in a real application before anything is sent to NuGet.org.

The publish workflow repeats the same package gates and retains the exact release candidates before publishing.

## Boundary review

The runtime/API surface is unchanged by this pass. No packaging framework, NuGet-specific runtime abstraction or dependency was introduced into Forge.Delta or Forge.Sync.

## Remaining executable gate

This artifact environment still has no .NET 10 SDK. The following claims therefore remain intentionally unmade here:

```text
dotnet build passed
dotnet test passed
dotnet pack passed
SDK package validation passed on the real packages
Native AOT publish passed
packed package consumers passed
```

The workflows now make those gates stronger. The next meaningful step is to run them in GitHub Actions and dogfood the resulting `.nupkg` artifact in Fulfilment/Inventory without vendored Forge source.
