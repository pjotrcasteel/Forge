01
Hard candidate boundary

A strategy should not decide whether it belongs to the problem.

The consumer defines a typed StrategySpace. A strategy outside that space is not “rejected” at runtime—it is never asked to compete. The package does not know what your spaces mean.

CONSUMER-OWNED BOUNDARY

The type marker says “which problem space”; registration says “who may compete”.

var interactive = StrategySpace<InteractiveSpace>
    .Define<WorkloadContext, WorkloadPlan>("interactive")
    .Add(new FastLaneStrategy())
    .Add(new BalancedStrategy())
    .Build();
02
Strategies propose; they do not execute

Only admitted strategies get to inspect the context.

Each strategy returns an applicable plan with an explanation, or an explicit rejection. Proposal evaluation stays side-effect-free so all alternatives can be inspected before anything irreversible happens.

NOT A CANHANDLE CONVENTION

Space membership and applicability are different questions.

Membership is architectural. Applicability is runtime domain logic inside an admitted strategy.

space membership→proposal→applicability
03
Freeze first. Select second.

The decision operates on evidence, not on registration order.

CompareAsync evaluates every admitted strategy once and freezes the resulting candidates. A selection policy then resolves that exact evidence set. The default is intentionally strict: exactly one applicable proposal.

04
Safe policy evolution

Run the next policy against the same world—not a second evaluation.

Because proposals are frozen before selection, production and shadow policies can select from identical evidence. Strategies are not re-run, and the shadow decision never executes a plan.

ONE EVALUATION · TWO POLICIES

Shadowing is selection comparison, not duplicate execution.

var comparison = await space.CompareAsync(context, cancellationToken);

var shadow = await comparison.DecideWithShadowAsync(
    context,
    productionPolicy,
    nextPolicy,
    cancellationToken);
05
Decision evidence

Answer “why did we choose this?” after the request is gone.

A completed decision retains candidate evidence. Forge can create a plan-free explanation, a deterministic SHA-256 receipt, and a diff against a later evaluation when context or strategy behavior changes.
