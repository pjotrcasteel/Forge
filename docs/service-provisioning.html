THE PLAN CROSSES A BOUNDARY

Turn it into data before execution.

SyncManifest creates a versioned portable description. ManifestDigest gives that exact plan a canonical SHA-256 identity for approval, storage or delayed execution.

04
Time passes

The dangerous assumption is that the world still looks like it did during planning.

Before the stored plan executes, another process applies an emergency api change. The old plan is structurally valid—but it is no longer valid against current reality.

PLANNED AGAINST
apirev 1stable
time→another actor changes state
ACTUAL NOW
apirev 7emergency-hotfix
!
MANIFEST PRECONDITION

Reject the stale plan.

ManifestPreconditions.Validate(...) reports api as changed since planning.

DO NOT EXECUTE

Forge does not make an old plan safe by optimism. It gives the application evidence that the assumptions behind the plan no longer hold.

05
Execution already started

Replanning gets harder once work has crossed the execution boundary.

Now imagine the first plan already started. A second desired state arrives. Simply discarding the old plan would lie about reality, because completed and running work still exists.

INTERVENTION policy-engine

The running operation's semantics changed. Application policy must decide what happens next.

SAFE CHANGE telemetry

SAFE CHANGE legacy-worker

Pending removal can be cancelled because the item is desired again.

NEW queue

A newly required operation enters the next plan.

That is the point of Forge

Make the transition explicit before side effects make it irreversible.

Delta explains the semantic change. Sync reconciles desired state. Dependencies make order explicit. Manifests preserve plan identity. Preconditions catch drift. Execution-aware replanning respects work already in motion.
